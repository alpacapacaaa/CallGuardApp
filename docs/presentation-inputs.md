## 슬라이드 8 — 하네스 엔지니어링 트러블슈팅: 실시간 통화 캡처

**[확정]** — 이번 세션에서 실제로 겪은 것이라 전체 서사를 재구성할 수 있음.

### 초기 목표
```
실시간 통화 음성 캡처 → STT → 보이스피싱 탐지
```

### 배경
2026-08-10 운영자 결정으로 라이브 캡처는 이미 Could(F-C4)로 격하되고 MVP는 파일 재생 입력으로 확정된 상태였다(PRD.md, plan.md Phase 1). 그런데 2026-08-11 앱 조립 단계(commit `91ce70e feat(app): CallGuardApp 실제 앱으로 조립 + 실시간 통화 캡처 지원`)에서 실시간 캡처 코드가 다시 붙었고, 2026-08-12 별도 세션에서 운영자가 이를 실제 통화(아이폰 Continuity, Mac에서 수신)로 테스트하며 트러블슈팅이 시작됐다.

### 문제 발생
> 실제 통화 음성에 실시간으로 접근하는 과정에서 문제 발생 — 상대방 음성이 전혀 감지되지 않음. 원인 조사 6단계, 5건 해결·1건 미해결.

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | 통화 중 음성인식이 아예 안 됨 | VAD가 8초 청크 **전체 평균** 에너지로 판정 → 발화 사이 자연스러운 침묵이 섞이면 실제 발화도 무음으로 오판, whisper에 미전달 | 100ms **슬라이딩 윈도** 단위 판정으로 교체 |
| 2 | 실시간 캡처만 켜면 앱이 통째로 멈춤(크래시·에러 없음) | whisper.cpp Metal GPU 초기화가 스레드 안전하지 않은데, 실시간 캡처는 상대방/내 마이크용 엔진 2개를 **동시에** 생성 — macOS 내장 프로파일러(`sample`)로 GPU 초기화 재시도 루프에 갇힌 걸 직접 확인 | 엔진 초기화를 `NSLock`으로 프로세스 전체 직렬화 |
| 3 | 캡처가 정확히 8초에서 끝남 | 청크 1개 전사 실패 시 예외가 캡처 루프 전체를 뚫고 나가 세션 종료 | 청크 단위 개별 처리, 실패해도 캡처 계속 |
| 4 | 에러가 나도 화면엔 "통화 종료 — 정상"만 표시 | 세션 종료 시 상태 메시지를 무조건 덮어씀 — 실패 메시지가 한 프레임도 안 보이고 사라짐 | 실패를 자막 로그에 ⚠️로 영구 기록 |
| 5 | REC 타이머는 도는데 새 자막이 영영 안 뜸(에러 없음) | macOS 오디오 장치 재구성 알림(`AVAudioEngineConfigurationChangeNotification`)을 처리 안 함 — 엔진은 "실행 중"으로 남지만 탭이 버퍼를 더 안 넘김(Apple 문서 명시 필수 대응 누락) | 알림 구독 + 탭 자동 재연결 |
| 6 (미해결) | 위 5개를 다 고쳐도 "상대방" 트랙이 통째로 무자막 | 시스템 오디오가 실제로 흐르고 있었다는 건 확인됨(마이크가 스피커 소리를 우연히 주워 "나" 자막에 영상 대사가 찍힘) — BlackHole 캡처 자체가 신호를 못 받는 것으로 추정되나 진단 로그로 원인 확정 전에 세션 종료 | **트러블슈팅 중단, 기능 포기** |

### 트러블슈팅
```
입력 방식을 실시간 통화 → 녹음본으로 되돌림
(= 2026-08-10 원래 운영자 결정으로 회귀)
```

### 결과
```
녹음 파일 → STT → 보이스피싱 탐지
→ 핵심 탐지 로직과 전체 파이프라인은 이미 이 경로로 검증 완료
   (M1·M3·M6·M7·M9 전부 PASS, docs/metrics-final.md)
```
