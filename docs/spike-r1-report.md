# R1 스파이크 리포트 — 통화 미러링 오디오 SCK 캡처 검증 (P1-T3)

> **보류 (2026-08-10)**: MVP 스코프가 파일 재생 입력으로 변경되어 R1 검증은 더 이상 프로젝트 임계경로가 아니다(PRD.md §6, plan.md Phase 1 참조). 라이브 캡처(F-C4)를 재개할 때만 이 절차를 다시 수행한다.

> **R1 가설(PRD §6):** "통화 미러링 오디오가 ScreenCaptureKit 시스템 오디오 캡처에서 제외될 수 있다."
> 이 리포트는 그 가설의 **Go/No-Go 실측 판정** 기록이다. 판정 주체는 운영자(청취), 증빙 정리는 에이전트.
> G-1 게이트의 핵심 입력이며, 결과에 따라 프로젝트 경로가 결정된다.

> **G5/G1 준수:** 실전화 산출 `remote.wav`·`local.wav`는 **저장소에 커밋하지 않는다.**
> 이 리포트에는 경로·길이·샘플 수·SHA256 해시만 기록한다. 오디오 내용 자체는 기록·복사하지 않는다.

## 2. 재현 절차

1. `docs/env-checklist.md` 전 항목 `[x]` 확인.
2. 상대방 음성이 필요한 실제 통화 준비(실제 발신/수신, 또는 상대방 쪽에서 음성 재생).
3. 통화가 연결된 상태에서 Mac에서 캡처 실행:
   ```bash
   cd <저장소 루트>
   .build/debug/CaptureDemo --seconds 20 --out-dir /tmp/r1
   ```
   - 정상 종료(종료코드 0) 확인. `/tmp/r1/remote.wav`, `/tmp/r1/local.wav` 2파일 생성 확인.
4. **판정:** `/tmp/r1/remote.wav`를 재생해 **상대방 음성이 들리는지** 청취 판단.
   - `local.wav`는 본인 마이크 트랙(참고용)이며 R1 판정 대상은 **remote.wav**다.
5. 아래 증빙 표를 채우고 1절 판정란에 Go/No-Go 기록.

```bash
afinfo /tmp/r1/remote.wav | head -6
shasum -a 256 /tmp/r1/remote.wav | cut -c1-12
```

## 4. 결과 해석 가이드

- **Go**: remote.wav에 상대방 음성이 명확히 존재 → SCK 경로 유효. 현재 캡처 아키텍처 유지, Phase 2 이후 진행.
- **No-Go**: 상대방 음성이 remote.wav에 없거나 극히 미미 → R1 현실화.
  - 에이전트는 **폴백(BlackHole 등)을 임의 착수하지 않는다**(AGENTS.md §3·G 해당).
  - 본 리포트와 함께 STOP 보고 → 운영자가 폴백 태스크(P1-F1) 큐 삽입 여부 결정.
- **판정 보류**: 오디오가 실리나 수준이 애매하면, 통화 볼륨·미러링 설정을 바꿔 2회 이상 재측정 후 기록.

## 5. G-1 게이트 연결

- 본 리포트 완료가 G-1 게이트(AGENTS.md §3.1)의 판정 재료다. **최종 Go/No-Go 판정은 운영자.**
- No-Go 시: plan.md 리스크 표에 따라 운영자가 폴백 태스크를 큐에 추가한 뒤에야 캡처 경로 변경 진행.
